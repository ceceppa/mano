# Changelog

A history of Mano's releases — what each version changes and why.

## 1.5.2 — August 24, 2026

`mano start` decided two things that were yours to decide, and `mano review` answered two questions that were yours to answer.

The `start` bugs were the same mistake wearing different clothes: a rule written to shape what `start` *proposes* got read as a rule about what you are allowed to *approve*. One refused a phase you asked for outright. The other quietly dropped two planning actions from an armed auto chain, and left `mano build`'s pre-flight to discover the gap a command later.

The `review` one is the fast close, and it is gone.

And `mano build` stopped building. Handed an approved auto chain, it wrote the ledger, told you what was in it, and ended the turn — three times in one session, each time waiting for you to type the command it was already running.

### Fixed
- **A correction you type into a running build is now as durable as one `mano review` finds.** Case (A) — a defect in work an existing row already promised — reopened the row and fixed it, and that was the whole record. `set-status --reopen` writes a status cell and prints `[reopened — report this]` to your terminal; once the fix lands the row reads `done` again and `progress.md` is byte-identical to a phase in which the defect never happened. Your words — the half that stops the row being rebuilt against the same text that permitted the bug — lived only in the conversation, which is precisely what Mano already says a confirmed defect must survive: `mano review` persists its findings as `R…` events *because* "a conversation does not survive a compaction, a restart, or an interleaved command." Same class of fact, and only one of the two channels had memory. Case (A) now writes the event first, from your exact words, and reopens after — so a run that dies mid-fix leaves the next `mano build` routing straight back to it under `REWORK:`, and `sign-off` refuses to close the phase while it is open. `request-rework` takes `--source review|build` so the ledger says which of the two raised it rather than crediting yours to a review that never saw it, and build resolves its own event in the run that fixes it. The one thing that would have deadlocked is written down too: an event build recorded during this run is not a pending event blocking this run.
- **Reporting a defect to a running build no longer costs you a permission round-trip.** Case (A) recorded the rework event, reopened the row, and then asked *"Should I proceed with this correction?"* — permission for state it had already written, about a defect you had reported one second earlier. A deviation stop exists to show you text Mano authored that you never approved: a `+N` correction row, an invented Exit criterion. A reopen authors nothing — the scope is your own sentence, the rows are addresses that already existed — so the question had no decision in it, and the answer was always yes. It was a bundling accident: the gate list carried "a row was reopened, or a correction row appended" as one bullet, and (C)'s real gate dragged (A) along with it. Build now records, reopens, fixes and resolves in one run, and names what it reopened in its closing line. A `source: review` event takes the same route — a finding you confirmed at `mano review` is at least as approved as one you just typed. The one case that still stops is the only part of it that is build's own judgement rather than your words: a reopen that reaches past what your report named — an Exit leaf that read `met` becoming unproven, or rows you never mentioned pulled in — stops before the fix and names them. The eval set had this right before the prose did: `build-correction-durable` already required the event to read `resolved` after the fix landed, which a run that stopped to ask could never satisfy.
- **A defect no longer reopens the Exit Criteria nearest to it.** Told that two scenes ignored the design brief, build reopened `E2a`/`E2b` — criteria asserting that four interruption outcomes look distinct, which was true before the report and true after it. Nothing about the defect touched them. It reached for the nearest leaves because no leaf covered the contract that was actually broken, and marking them unproven records a promise as open when it was kept. An `E` leaf is now reopened only when the defect contradicts what that leaf asserts.
- **A component the design brief names is a promise, not a reference.** Anima phase 22 added two playground scenes with raw title labels and ordinary buttons, while `design-brief.md`'s own composition entry for that phase named the shared `ExampleHeader`, `SelectorDock`, and playback controls — all three already built, sitting in the same folder. Nothing failed. Every gate that could have fired is an *absence* gate: 0c.0–0c.3 and 6.2–6.4 all check whether an artifact left a decision unmade, and this artifact had made it. The acceptance-evidence gate cleared too, because `Exit Criteria` test what a surface *does* — "every supported Control reaches its final position", "each interruption shows a distinct outcome" — and a hand-built lookalike does exactly that. So the phase reached all four criteria with the design contract unbuilt, and the ledger read `done` across the board. The real gap was narrower than it looked: `project-rules.md` has had a mandatory obligation→row map since the July documentation-rule incident (**0g**), and `design-brief.md`, which carries obligations of identical force, had none — it was read at 0b and then consulted "when you reach the row that needs it", which is the relevance judgement 0g exists to abolish. **0g.1** now maps the brief's `### [PHASE_ID] — [Screen Name]` entries the same way: every named component lands on the Scope row that must instantiate it, and one with no row to carry it stops the run with no ledger written. Gate **10.2** is the other half, and both halves are needed — a map made before code is exactly what a long implementation pass forgets, and nothing downstream re-reads it. It checks this turn's actual edits for each named component and leaves the row **pending** when one is missing. Reusing the shared theme is not reusing the component; building something that renders the same is not reusing it either.
- **`mano build` runs the whole phase, in one invocation, in both modes.** An armed chain reached build, which ran pre-flight, wrote `progress.md`, reported "four scope rows; the first is `S1a`" — and stopped. Nothing was built. Three causes, all of them structural. The projection build reads on its first run led with a `DEV:` line saying *"in auto the implementation entry is mano build"*: a sentence addressed to a different reader, sitting where build looks for its instruction, telling build to tell you to run build. It now gets a `BUILD:` line of its own naming the whole invocation — pre-flight, `init`, then every row to completion — and `DEV:` no longer names an action its own reader cannot take. Once a ledger exists the projection adds `RUN:`, which states the run and the counts still open rather than only the next row. And build's contract said "return to step 2 for the next unresolved row **in the same invocation**" about row-to-row, with nothing at all covering ledger-to-first-row — so a run that stopped there broke no rule it could point to. Creating the ledger is now named as what it is: something that happens inside a run, never something a run is finished having done.
- **The rule that would have caught it was in a file `mano build` can never open.** *"If you have written words describing what you are about to run, you have not run it"* lives in `_mano/rules/auto.md`, which only the planning skills load — `build.md` and `dev.md` declare `requires: [implement]` and nothing else, deliberately, so their prompt prefix stays cacheable. `implement.md` already duplicated the auto chain's *closing block* for exactly that reason but had copied only that half. It now carries the other half too, as **Never end a turn on an announcement**, with the complete list of what counts as a stop — and the note binding the two copies together now says plainly that a rule living only in `auto.md` does not exist on the implementation path at all.
- **A chain no longer ends on the menu it was about to walk past.** `mano ui` finished the planning half of an armed chain, printed `Next: mano build` among four options, and handed back — after which the human asked why build never ran. Two rules were in direct conflict: `core.md` says a mid-chain hand-off omits `Next:` entirely, while each planning skill's own contract said to show `mano build` as the `auto` next step. The skills now defer to the chain rule at that seam: a `Next:` block is for a human choosing a command, and mid-chain nobody is.
- **A scope you name is scope, not a proposal to negotiate.** Asked for two unrelated backlog items in one phase, `mano start` answered "I won't combine them" and offered a pick-one menu. The one-outcome-per-phase constraint is real and stays — it is what lets a phase review return a verdict you can act on — but it governs the shortlist `start` *suggests*, never the boundary you draw. It now takes the scope, says the cost once as a `⚠ Verify` (one phase, one verdict covering both), and drafts the brief in the same turn. A refusal, a pick-one menu, or the same question asked again are no longer moves it has.
- **Phase size is measured in effort, not item count.** "Suggest a shortlist — 1-2 items if complex, several if small" was one soft sentence sitting under a heading that shouted **Hard constraint**, and it lost every time. It is now its own rule: a cluster of small items is not over-scoped by virtue of being a cluster, and one large item is not right-sized by virtue of being alone.
- **A phase brief can hold a combination you approved.** When the scope spans more than one outcome, the brief carries them as separate `## Phase Scope` categories with their own exit criteria, and `## Phase Goal` names the one that survives a scope cut — rather than inventing an umbrella outcome to cover both, or dropping the item `start` would not have proposed.
- **`ARTIFACTS:` reports existence, never coverage.** `mano start` builds its auto chain from an existence-only projection and may not open the artifacts — by design, so scoping stays cheap. It read `ux-flow=present design-brief=present` as "this phase is covered" and armed `start → spec → build` for a phase adding a third category to a two-category selector. Both files are project-lifetime: once written they read `present` for every phase that follows, so presence can never tell a covered phase from an uncovered one. Being blind now resolves toward including the action — a phase touching an interactive surface or a rendered screen gets `ux` and `ui` in the chain, and you strike what you don't want with `go, skip ux`. "The phase only adds one more of something that artifact already describes" is named as the reasoning the rule exists to block.
- **`_mano/rules/artifact.md` no longer claims `mano ui` is safe from that trap.** Its asymmetry note was right about the planning decision tree, which can see the phase preview, and wrong about the auto-chain path, which cannot. Both frames now agree.
- **The same work stopped entering the backlog twice under two names.** Asked to add *"Motion interruption example coverage"* to a phase, `mano start` scoped that item correctly — and then wrote a second one, *"Motion interruption example scenarios"*, for the same work. Both landed `in-phase-22`, so the phase looked right and the backlog quietly grew a twin. The same pair sits earlier in that file (*Add "Showcase" category to demo selector* beside *Showcase category in demo selector*), so this was not a one-off. The cause was a rule with nothing behind it: "before adding an item, check for duplicates" has been in `start.md` since before the token work, but `backlog.md` is write-only there and `SCOPE INPUT` carries open items only — so an item already scoped or already shipped was invisible to the skill told to check for it. Two things now stand behind the rule. `state.js --titles` gives every skill a cheap look at what the project already tracks — every title, type and status, no context, 20 KB against a real backlog's 165 KB — which is what actually prevents the duplicate. And `backlog.js add` is the backstop: it names any item whose title merely resembles an existing one, including items already scoped or resolved that no projection shows. **It writes everything and blocks nothing.** The check over-fires by design — no title metric separates a real duplicate from a real sibling, so *Sequential* beside *Parallel group playback mode* trips it too — and a check that noisy has no business stopping you. It reports, `start` passes it on as one `⚠ Verify:` line, and you decide whether two items are really one.
- **When you name a piece of work, `mano start` now finds your item instead of writing its own.** You almost always name something because you read it in the backlog. It matches your words to a real title (`state.js --titles --match`), assigns *that* item, and quotes the real title back — rather than re-wording your request into an item of its own invention, which is what left the item you meant untouched while its near-twin entered the phase.
- **`backlog.js update` — the rewrite every skill was already told to do and none could.** "If an existing item covers the same topic, update its context instead of creating a duplicate" has been in `start.md` since the beginning, and the split step tells `start` to rewrite an item's title and context down to the slice entering a phase. Neither was possible: the script had `add` / `assign` / `resolve` / `resolve-gap` / `reject` and nothing that edits an item, while two other rules in the same file said the only permitted hand-edits were `## Core Product Principles` and — circularly — the split. `update --title "..." [--new-title "..."] [--context "..."]` closes it. It changes the title and context and nothing else: `Type`, `Source`, `Track` and especially `Status` are left alone, because status carries phase identity and belongs to `assign` / `resolve` / `reject`. It refuses without writing on a missing, ambiguous or malformed target, on a rename that would collide with another item, and on a context over the five-line limit. The split now calls it instead of hand-editing, which leaves `## Core Product Principles` as the only thing in `backlog.md` anyone edits by hand — and when the resemblance report is right, folding your version into the item that already covers the work is now a command rather than a shrug.
- **`4. 📋 Show full backlog` does something now.** The scope menu has offered it for months while the skill was forbidden to open `backlog.md`, so it was an offer nothing could fulfil. It runs the roster projection and shows the whole backlog grouped by status — including items already scoped or shipped, which the scope candidates deliberately omit. `3. 🎯 I know what I want` and `5. 🆕 New idea` were equally unhandled and now have written behaviour too.

### Changed
- **`mano continue` resumes the work instead of telling you what to type.** With an open ledger it used to print a status card ending in "Use `mano build` to resume" — you typed `continue`, and got back the command you would have typed instead. `continue` is already the go-ahead. It now dispatches: `mano build` runs to completion, `mano dev` implements one story and hands back (the batch stays something you opt into by typing `yolo`). The choice is not a judgement call — `state.js` evaluates the six clauses of **Implementation entry** and prints the answer as `IMPLEMENTATION_ENTRY: build | dev | none`, so the rule finally has one implementation instead of six sites re-deriving it from file listings. `none` still means what it always meant: an invalid ledger, a phase ready for review, or the one fork Mano leaves to you — a scoped phase with no ledger in `manual`, where `mano stories` and `mano build` are both genuinely right.
- **The fast close is removed. Nothing about a phase closing is an answer to a question Mano asked you.** `all works as expected, close it` used to close in one exchange and write the record itself — every Validation Question stamped `unanswered at close`, the decision stamped `Not assessed`. That is a record with holes in it, produced by the one path designed to be frictionless, and the holes were invisible until you read the file later. Three slots are now yours alone and Mano will not write any of them: what happened, each Validation Question, and the decision. `close it` remains full sign-off on the *phase* — exit criteria still flip to `met` with your name and the date, assumptions you shipped on still record as `accepted`. It is simply no longer mistaken for evidence.
- **The gate costs one exchange, once — and it exists to tell you what you were about to skip.** You did not write the brief's questions and have no reason to remember them at close time. So a close that leaves any of the three open buys a single line naming exactly those, all of them at once, never one question per turn: `still need: Q2 — Does a busy tag stay usable on a phone? / Decision — …`. `didn't check`, `nothing to decide`, and `didn't test it` are complete answers, recorded as yours. A reply of `skip it` closes the phase on the spot. Nothing else rides along in that line — the triage, the phase checks, and the assumptions you already confirmed are written the moment the gate clears.
- **Review never asks what you decided.** The first cut of the gate had three slots and the third was wrong: no phase brief states a decision. `## Validation Plan` holds `### Questions` and `### Try`, and nothing else — so `Decision — [the choice this phase informs]` had nothing to name and printed at you as a literal empty bracket. The Decision is recorded from what you already said, or `Nothing to decide`, and is never gated. A legacy brief carrying an explicit `Decision this informs` heading is the one exception, because that brief does name the choice. Two rules fell out and are now written down: never send a chat line whose bracket you could not fill from the brief, and never send a second `still need:` message in one review.
- **The gate reply is feedback, not just an answer slot.** Answering `Q1: I couldn't test this manually, we need to implement it in the existing examples` used to lose the second half — the gate said "nothing else rides along", which was meant to stop Mano re-presenting settled triage and instead stopped it hearing anything new. That reply is now triaged in full: `Q1` records `not checked`, and the example-coverage request becomes a backlog item. Mano adds nothing to that message; you may add anything.
- **The review opening stopped burying its questions.** They were listed as `Open question Q1: …`, which reads as context to skim past rather than something you owe an answer to. They now sit under `Answer before close:` with the decision beside them, which is what they always were.
- **`unanswered at close` and `Not assessed` no longer exist.** They were the only two values in a review record that meant "Mano filled this in for you", and the gate makes both unreachable. `not checked` replaces the first and is written only when you say so; `Nothing to decide` replaces the second on the same terms. `mano start`'s warning about closing on an unanswered question now keys off `not checked`.

- **`mano start` stopped writing validation steps you cannot perform.** Anima phase 21 shipped `Try: Start conflicting motions under each supported interruption choice and observe the resulting property state` — while every Phase Scope leaf was engine behaviour and the one demo leaf merely listed an existing grid demo under a new category. Nothing ran a conflicting motion where a person could see it, and the debugger panel that would have was deferred. The only way to answer the question was to implement a scene first, which is not validating. Every `Try` is now checked against the surface it needs: a Scope leaf ships it, or the project already has it *and it exercises this phase's behaviour* — an existing demo of something else does not count. The tell is named too, because it was sitting in that brief in plain sight: a leaf called **Observable outcome** and a design principle reading *make the intended result easy to inspect*, with nothing in scope making anything observable. `start` may not resolve this quietly in either direction — adding a surface widens scope, dropping a question discards learning — so it asks before drafting. This mattered more once the answer gate landed: review will now *demand* an answer to a question the phase made unanswerable.

### Added
- **`_mano/scripts/chain.js`** — the one part of an armed auto chain that cannot be recomputed. Everything else about a chain is derivable at any moment: the artifacts on disk say which planning actions have run, and the ledger says whether implementation is done, so a dead session costs nothing to recover from. The exception is a chain you *edited* — `go, skip ux` — because recomputing it re-proposes the action you just declined. `mano start` now records that subtraction, and only that, when the approval reply removes an action; a chain approved as proposed writes nothing at all. It is stored in local Git config beside `mano.mode`, for the same reason: how you are running this clone is not a property of the project and is not committed.
- **`_mano/VERSION`** — installs now carry their own version stamp, so a project can tell which Mano it is running without guessing from behaviour.
- **`tools/check-version.js`** keeps `src/VERSION` and `package.json` in lockstep. `npm version` bumps package.json and nothing else, which is exactly how the two drift, and a stale `_mano/VERSION` is worse than none — it reports a version whose behaviour the install does not have. The guard runs in `npm test`, on `npm version` (with `--fix`, so a bump cannot leave the file behind), and at `prepublishOnly`. `npm run version:sync` fixes drift by hand.

## 1.5.1 — August 21, 2026

Implementation stops telling you how to manage your own context.

`mano build` and `mano dev` both ended their hand-off by instructing the human to start a fresh session. That instruction existed to save the framework tokens, not to help the person reading it — and because it sat where a command normally sits, it read as a requirement. It never was one: `progress.md` and `stories/README.md` are the durable state, so a resume costs a projection read from any session, new or continued.

### Changed
- **The implementation hand-off names a command, not a chore.** `mano build`'s mid-run stop now ends `Next: mano build — continues at S3.`, and `mano dev` ends `Next: mano dev for the next story.` This is the `Next:` convention every other skill already followed; implementation was the one place that broke it by substituting session management for the next action. Where to resume is the human's call — a long build is often exactly when you want to keep the context you have.
- **`mano build`'s mid-run stop is motivated by row boundaries, not by token economy.** The rule was "stop when this turn's output budget is spent"; it is now "stop at a row boundary, never mid-row". The behaviour is the same and the reason is better: a run that trails off inside a row leaves work the ledger cannot describe, which is the one state a resume cannot recover from. Pass sizing is untouched — a pass is still only as large as what can be implemented *and verified* in the turn, which is the gate that actually prevents half-done rows.
- **Session hygiene is agent-side guidance.** `_mano/rules/core.md` still prefers one story per session and still explains why replaying a long session is expensive. It now says explicitly that this governs where the agent ends a turn and is never printed at the human as an instruction.

## 1.5.0 — August 21, 2026

`mano build` — a second way into code, for phases that do not need story files. The unit of work becomes the numbered `## Phase Scope` item the human already approved, so nothing invents a decomposition and nothing can drift from the brief. The saving is not in skipping files; it is in not needing the guard rails that discipline an invented unit.

Around it, three things that are not about `mano build` at all: every writer now survives an interrupted write, review costs one exchange again, and the auto-chain rules stopped being resident on manual runs.

### Added
- **`mano build` (`_mano/skills/build.md`)** builds the active phase straight from its brief. Pre-flight runs **once, whole, against the whole brief and before any ledger** — every present artifact read, the hard gates, project-rule mapping, then a proof that every `Phase Goal` outcome reaches a Scope leaf and an Exit leaf. Anything unresolved stops the run with nothing written, which is the cheapest place it can stop. Then it implements row by row and stops only when it *deviated*: a gap, a scope conflict, a split, a reopened row, or a mid-phase correction.
- **`PHASE_DIR/progress.md` — the build ledger.** One `S` row per Phase Scope item, one `E` row per Exit Criteria leaf, addressed by the brief's own numbers (`S2`, `E2b`). Two status vocabularies, enforced by the writer: scope is `pending | doing | done`, criteria are `pending | met | needs-human`. **Built is not proven.**
- **`needs-human` — a third Exit status, and an honest one.** A criterion that is inherently visual or experiential cannot be exercised by the implementing agent, so it is handed over with a recorded reason instead of being claimed. It is a terminal handoff, never an escape hatch for a missing test, unavailable tooling, or a failed check — the writer refuses it while any scope row is open — and review shows it to you with its reason and the brief's matching `Try` line.
- **`progress.js` — the ledger writer, and `init` takes no content.** It parses `## Phase Scope` and `## Exit Criteria` out of the brief and emits both tables itself, so verbatim copying stops being a rule a model can follow or violate and becomes a property of a parser. It also owns the refusals: `met` on a scope row, `done` on a criterion, a backwards move without `--reopen`, splitting a row that is not being built, a parent closed before its sub-rows, a correction row under an item the brief never had.
- **One grammar for the ledger, in `ledger.js`.** The writer and the state projection used to carry a row pattern each, and the two disagreed: a lettered row was a nested brief leaf to one and a human correction to the other, so the leaf's behaviour line was silently dropped. One module now owns the whole address space (`S2`, `S2a`, `S2+1`, `S2.1`, `E2a`, `R1`), which makes that class of disagreement inexpressible.
- **`## Row Contracts` — exact text, verbatim and readable.** A correction or a split carries its own contract text in a fenced block keyed by row id, so pipes, quotes, newlines, and backticks round-trip. The table cell keeps a short derived label for scanning. `progress.md` stays a file you can read.
- **Durable review findings.** A confirmed negative finding at review becomes an ordered `R…` event in the ledger, with the human's own words. A conversation does not survive a compaction, a restart, or an interleaved command, and a confirmed finding must: while any event is pending, state routes the phase back to `mano build` even though every row reads `done`, and review refuses to close.
- **`mano build "[what changed]"`** — corrections typed at invocation go through the same classifier as corrections typed mid-run. A defect in work already marked done reopens those rows; an in-goal nuance is appended as a `+N` row **in your own words**, linked to the Exit Criterion it changes; a genuinely distinct outcome writes no row and no code and is offered to the backlog with its complete item previewed for approval. With no ledger there is nothing to correct, and it routes to `mano start "[the change]"` instead.
- **`mano start "[what changed]"`** revises the current brief in place while the phase is still scoped and nothing is being implemented. It shows the complete revised scope and writes nothing until you approve it; that approval *is* the approval of the changed contract. Once a ledger exists the brief is frozen and the amendment is refused — which closes the `build → start → stories → start` loop the old route produced.
- **`_mano/rules/implement.md` — one implementation contract, two units of work.** The half that is identical for `mano dev` and `mano build` (gap gates 6.2–6.4, pre-reads 7–10, the acceptance-evidence gate 10.1, Repair Mode, the read budget, Implementation Output Discipline, and the auto-chain closing block) now has one home; both skills declare it in `requires:`.
- **`_mano/rules/auto.md` — the chain rules, loaded only under `MODE: auto`.** The pause rule, continuing-is-an-action, and the closing block left `core.md`. In `manual` — the default, and the common path — no skill opens the file at all, which takes ~4.6 KB off every planning command's resident context; `mano review` keeps the saving in both modes, because it is always human-run and outside the chain. `npm run stacks` prints what each command loads in each mode, and `node eval/check-refs.js` fails if a conditional fragment is ever declared unconditionally.
- **Addressable everything.** Briefs carry a numbered `## Phase Scope` and two-level `## Exit Criteria` (numbered category, lettered leaves), plus stable `Q1…` addresses on Validation Plan questions and `A1…` on Assumption Log rows. Every leaf is proven separately, so a category marked satisfied can no longer hide an unverified bullet inside it — an improvement to `mano dev`'s gates on the existing path too. A brief written before the addresses existed is never rewritten: the same ids are derived by document order.
- **`Validate now:`** — when implementation leaves the phase ready for review, it hands you the brief's own `Try` guidance under that heading. This is the single sanctioned expansion of implementation's one-line terminal rule, defined once so build, dev, and the auto chain cannot disagree about it.
- **A measured eval harness.** Cases can now run ordered multi-step sessions in one retained project (`mano build`, then `mano review` in a *fresh* session), the `claude` runner reports real per-step token usage and the resolved model, and every measured run appends a manifest record. A metric a runner cannot expose is `null`, never `0`. The two-phase extension fixture — phase 2 building on a finished phase 1 — is the scenario Mano most needed and did not have.

### Changed
- **Auto mode's terminal action is `mano build`** where it was `mano stories` → `mano dev yolo`. Nothing else in the chain changes, and the terminal action is not configurable — a knob there would be one more decision for no gain. A phase that already has a stories index keeps the stories path.
- **Every writer is atomic, and every mutation is guarded.** `progress.js`, `stories.js`, and `backlog.js` write through a shared same-directory temp file and rename, so an interrupt mid-write leaves the previous file intact — the one real data-loss path a single user has. Every mutating command takes `--expect-phase-id` and refuses on mismatch, so an owner change between two commands cannot mutate another owner's phase.
- **A malformed ledger is `invalid`, never "missing".** A `progress.md` that exists and does not validate is a hard stop with one repair instruction: delete it and re-run `mano build`. Reading it as *no ledger* used to skip the dual-ledger refusal entirely, which is precisely when that refusal matters. Duplicate Exit ids are rejected the way duplicate Scope ids already were.
- **Resume picks the deepest open leaf.** A split parent in file order used to win over its own pending part, so a fresh session resumed the roll-up instead of the work.
- **`mano review` is a short triage inbox.** The opening is one response and one ask: every Exit leaf on its own line at its own address, each with the brief's `Try` guidance, an `Open bet` per assumption, an `Open question` per unresolved Validation Question. Mixed feedback echoes only the findings Mano classified — the record stays complete, the echo does not read it back. No tags, no status vocabulary, no menu of closers.
- **`close it` is full human sign-off.** You typed it; that is an attestation, and recording it as untested would be the framework second-guessing you. Every `pending` and `needs-human` Exit leaf flips to `met` with `human sign-off at review, <date>` recorded against it, and the assumptions the phase shipped on record as `accepted`. A Validation Question you never answered records as `unanswered at close` — shipping is not an answer to a question you asked. `close it` beside a defect closes the phase and asks whether the defect goes to rework or is dismissed in your words; it never erases it.
- **`state.js --next` serves both implementation paths** and projects the ledger's two tables, the next non-done row with its exact contract text, the artifact inventory, and any pending review findings — before the ledger exists as well as after, because build's first run is exactly when pre-flight needs the inventory. `--current` adds `PROGRESS` and per-table counts. A phase holding both a stories index and a ledger is **refused**, not silently resolved.
- **Mid-phase corrections stay inside `mano build`** instead of bouncing out to `mano stories`. Most of them are a defect in work already marked `done` — a status correction that reopens the row and invents nothing at all.
- **Grouping, with the ceiling you wrote.** Adjacent leaves of one Scope category can be built in a single pass when they are genuinely one piece of work. The category boundary is the ceiling, corrections and splits never join a group, and every leaf still carries its own evidence: a pass covering three leaves and proving two closes two.
- **A terminal evidence sweep before the phase reports built.** A criterion marked `met` under row 2 can be regressed by row 6, and the status still reads `met`. Before the terminal line, build re-runs the whole-brief checks against the artifacts as they stand now, re-runs verification, re-evaluates every leaf against final evidence, and reopens anything later work invalidated.
- **`core.md`, `AGENTS.md`, and `.cursorrules` agree that `mano build` exists.** `core.md` said "There is no mutable progress ledger" and exempted only `mano dev` from the code refusal; `.cursorrules` never dispatched `mano build` at all. Both implementation actions are now named, and what is forbidden is *inventing* state, not keeping it.
- **`verify.js` reports honestly.** An empty argument survives, a missing executable and a killed process are reported by name instead of as a bare `exit 1` over a blank excerpt, the stdout/stderr excerpt no longer claims an interleaving it cannot deliver, and the character cap keeps both the head and the tail it just built. `--help` prints usage instead of running `--help` as your command.
- **A stated technical directive that no feature item owns now gets its own backlog item.** B1's pass-through told intake to preserve a directive "in the relevant item's context" — which quietly assumed one existed. The project-wide ones have no relevant item: a runtime version, a module system, a folder structure, a file-naming scheme span every item and attach to none, so a PRD's `Project directory structure` block reached the backlog nowhere and the implementer invented its own layout. Intake now homes those as `spec-gap` (the tech spec will own it) or `rule-gap` (project rules will), carrying the stated values. The gap type is a routing address, not a verdict: `state.js --scope` already excludes gap items from phase selection, and `--spec` / `--gaps rule-gap` already put them in front of their owners. `mano spec` and `mano rules` now treat a directive-carrying gap as authoritative user intent under the same override-flag duty the brief's `## Stated Technical Preferences` block already carried — adopt it, or override it in writing with the reason.
- **`OPEN_GAPS:` on the decision `mano start` reads.** Gap items are excluded from scope selection by design, which meant a backlog with any scopeable item hid them completely — including a directive homed there precisely so it would survive. The routes now print alongside the decision, and `mano start`'s next-action block keeps them visible without letting them displace its recommendation.

### Hooks
- **`## Inputs` now has a contract.** Every shipped hook declared one; nothing said what Mano did with it. A `check` hook reads exactly those paths itself (projection fields like `BRIEF` / `PREVIEW` resolve from the state projection, never by hand); a `suggest` hook hands the resolved list to the external skill — *"Allow the review skill to read: …"* — so the reviewer's scope is the hook author's choice rather than whatever it decides to open; a `command` hook's is inert.
- **A `check` hook may not out-read its own skill.** It is Mano applying the checklist, so it inherits that skill's read boundary. `mano review` never reads source, so a check hook on review may not ask it to — that comparison is exactly what `post-review` ships as a `suggest` hook for.
- **The shipped example checklists are commented out.** A check hook is the user's own review, so an activated example now applies nothing until its items are uncommented or replaced. Mano never invents checklist items and never falls back to the example text. `.example.md` files are never loaded at runtime, so the examples cost no context.
- **`post-rules` and `post-ui` gained the phase brief** as an input; `post-start`'s was de-hedged. A hook checking a phase-scoped artifact could not previously see what the phase asked for.
- **`## Run` appears only in `post-review`**, the one `suggest` example. It is the suggest-mode section; in a check hook it would never run.

### Notes
- `mano stories` + `mano dev` are unchanged and stay first-class: they keep the big-model-plans / small-model-implements split and suit a large phase. A phase uses one path or the other.
- **There is no v1 ledger migration, and there will not be one.** `mano build` had never shipped, so no `progress.md` exists outside this repository. The corrected grammar is the only grammar.
- **Every shipped incident rule now names a real eval case.** Three carried `eval=pending`; a build gate copied from the stories path now carries its own provenance and its own build-path case, because a green stories case proves nothing about a unit of work that is a Scope leaf. `eval/pending-evals.json` is the recorded, temporary exception a new `pending` needs — and it ships empty.
- `mano owner` / `mano mode` / `mano track` are documented as what they are: thin, validating wrappers over `git config --local mano.<key>`, with the exact equivalent for each command in the README.

## 1.3.0 — August 10, 2026

### Added
- **`mano mode auto|manual` adds an explicit, local hands-off option** — `manual` remains the default. After the human approves a phase scope, auto mode runs the approved, phase-specific planning chain through `mano dev yolo`, pauses for every human decision or blocker, and always stops before `mano review` or another phase. The mode lives in repository-local Git config, can be overridden with `MANO_MODE`, and is projected by every `state.js` view, including gap-only and JSON output.
- **`mano track` adds an optional local experiment filter** — imports and conversational Start items receive the active Track, approved briefs preserve it, and review-created items copy the phase Track. Start can also filter one run by Source, Track, or their intersection without changing priority, scope, or approval.
- **Hooks now support deterministic `command` mode** — a command hook names one project command that runs after its skill in both manual and auto modes. Existing and mode-less hooks remain `suggest`: Mano asks before running them in manual or unarmed work, while an approved auto chain runs them as the substitute for skipped intermediate human review and pauses if their findings need triage.
- **Exact backlog items can be pulled into an open phase through `mano stories`** — when the human names an existing item and it fits the already-approved goal, stories may assign that exact title with the backlog writer and add a lettered story. It cannot choose work, hand-edit the backlog, broaden the phase goal, or bypass the normal readiness gates.
- **Greenfield scaffolding now has a non-destructive runner** — `scaffold.js` runs empty-directory project generators outside the project, preflights every destination, preserves identical files, rejects differing collisions before copying, and never overwrites or deletes existing Mano artifacts. Spec, stories, and development contracts require this guarded path instead of moving `_mano` / `_mano_output` away or hand-merging generated files.

### Changed
- **Auto chains are approved run plans, not repeatedly guessed next steps** — `mano start` performs a narrow project-artifact check before proposing the chain, preserves its ordered remaining actions across pauses, refreshes mode at each handoff, and resumes in the same turn after an answer is captured. New evidence can still pause or invalidate the plan; the agent never answers a fork for the human.
- **Auto planning now keeps material UX and UI work visible** — a new interactive frontend includes `mano ux` and `mano ui` in its proposed auto chain when the exact flow, responsive composition, hierarchy, or visual states are not already covered. Familiar controls are not treated as a substitute for product decisions; only the human may explicitly skip those actions.
- **New repeatable artifact categories keep `mano rules` visible** — a phase that introduces a recurring file, module, component, document, example, or asset shape is treated as new rule territory even when a substantive rules file already exists.
- **Phase closure no longer masquerades as validation** — phase briefs now state the human decision a phase can inform and the evidence to gather. `mano review` records a compact validation-and-decision log instead of a release recap, keeps assumption outcomes separate, and preserves `close it` as an immediate `Validation: Not tested` / `Decision: Not assessed` close instead of making feedback theatre mandatory.
- **Every Mano artifact and user prompt now follows one clarity contract.** Skills name actors, triggers, outcomes, and boundaries. Questions name the decision and its consequence without forcing one question per turn. Skills avoid jargon and unsupported marketing language. They unpack dense conditions into ordered steps. Technical details stay in their canonical artifact. Product feelings remain valid human learning questions.
- **Phase learning plans now use direct Questions and Try lists.** Each question has a matching test. Capability checks remain in Exit Criteria. `mano review` keeps learning and completion separate.

### Fixed
- **Auto scope approval and run approval are no longer ambiguous** — at the scope prompt `1` and `go` are exact synonyms that approve the scope and arm the displayed chain; edit-only replies revise the proposal without starting it.
- **Stories no longer rationalises away a missing planning artifact** — material UX, UI, rules, or contract gaps always pause for the human, even when an earlier auto plan omitted the artifact or the interface looks conventional.
- **Auto hook semantics no longer contradict themselves across skills and templates** — workflow, bootstrap instructions, every Mano skill, hook documentation, and example hooks now agree on manual suggest, auto suggest, and always-on command behavior.
- **`mano dev yolo` and auto-mode summaries no longer have incompatible output contracts** — standalone YOLO still emits exactly one aggregate line; as the terminal auto action, that line is followed only by the required auto closing block.
- **Paused chains no longer lose their continuation state** — the closing block records `Remaining:` actions, decision answers become mid-chain logs when appropriate, and switching to manual while paused cleanly hands control back instead of continuing from cached mode.
- **The mid-phase assignment path no longer conflicts with stories' write boundary** — the hard no-implementation gate and Forbidden section now name the single writer-mediated backlog exception while continuing to reject every direct or unrelated artifact edit.
- **Review can no longer hide an Exit Criterion behind the learning plan.** The opening prompt lists every phase promise. The review log records each promise. Results use passed, failed, or not tested. `close it` records unchecked promises honestly.
- **Review no longer grades optional validation context.** A whole-review verdict such as `all went as planned, close it` records the result, passes the listed phase checks, and confirms the presented assumptions. Where or how the human checked it remains optional. Missing fields disappear instead of showing `Not recorded`; bare closes record `Not tested`.

- **Story status updates now have an atomic postcondition.** A missing requested row fails before any status changes, and Dev verifies the updated state before claiming completion.

## 1.0.0 — Initial Release: June 18, 2026

Mano started from a simple frustration: heavyweight AI planning frameworks ask you
to think everything through upfront, generate large documents, and trust agents to
run with them. Mano takes the opposite bet — that software rarely moves in a straight
line, so planning should stay cheap to revise and the human should stay the judge at
every step. It is a supervised, à la carte planning protocol for coding agents:
small shippable phases, only the context the current phase needs, and artifacts that
are explicit, human-readable, and disposable when they stop being useful.

This first release makes Mano installable and settles its core surface after a long
period of refinement against real projects.

### Key Features
- **À la carte, not a pipeline** — a minimal path of a few commands; every other
  planning action (`spec`, `ux`, `rules`, `ui`) is optional context-tightening you
  run only when the current phase needs it.
- **Phases as the unit of work** — each phase is scoped, built, reviewed, and closed
  as one coherent, independently verifiable slice, with the human approving at each seam.
- **A thin implementer contract** — `mano dev` implements one story against its
  acceptance criteria and stops; one-line output, no narrative, no scope creep.
- **Action-named skills** — `mano start`, `mano spec`, `mano stories`, `mano review`,
  and more, each a focused constraint lens that reads only what it needs.
- **`npx mano-plan install`** — one command drops Mano into any project; re-run it to update.
- **Token-efficient by design** — Mano loads one skill at a time rather than a whole
  pipeline, and keeps the implementer's per-story contract small, so the build loop
  spends its context on your code rather than on the framework.

### Limitations
- Single-threaded by design — one phase at a time; concurrent multi-team work on the
  same phase track isn't supported.
- No automated test/eval suite yet, so the framework's quality rests on human review.
- Behaviour depends entirely on the agent's instruction-following; smaller models can
  still drift, and the human remains the enforcer of scope and quality.
